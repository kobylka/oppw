# Executable cross-component contracts

These fixtures are consumed by `tools/validate_contracts.py`. They are not sample UI data and must not be independently reimplemented in tests.

The validator runs this boundary with real components:

```text
fixture → coordination.php / service-control.php / strategy-controls.php → ingest.php → disposable MySQL
        → status.php / analytics.php / mobile-receipt.php / service-control.php / strategy-controls.php
        → Android JsonParser JVM test
```

`fixtures/open-position.json` describes one open position, a lifecycle with deliberately distinct timestamps, deterministic closed trades, daily closes, and two intraday lows. The contract verifies that portfolio metrics use daily first/low/close equity, while closed trades alone define the episode list and minute equity refines the episode trough. It also verifies the 24-hour episode threshold. `expectations.json` records stable semantic expectations. Dynamic timestamps, specification hashes, decision IDs and authentication tokens are generated by the validator.

When a contract changes, update the producer, PHP, schema/migration, API, Android model/parser, fixture, expectations and assertions in one change set.
